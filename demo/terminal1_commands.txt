====================================================================
WHAT TO EXPLAIN
====================================================================

Why this exists:
  The most common way student ML projects lie to themselves is data
  leakage -- near-duplicate images ending up in both train and test,
  which inflates accuracy because the model is recognizing the image,
  not the disease.

ct_leakage_audit.py -- say this:
  "This hashes every CT image, finds near-duplicates with perceptual
  hashing + structural similarity, and checks whether any duplicate
  cluster got split across train/val/test."
  Point at: "clusters split across train/val/test: 0 / 111"
  "Zero. Our first CT model scored 100% on a random split -- this audit
  showed 35 of 109 test images had a near-copy in training. After the
  cluster-aware resplit there are no leaks, and the CT test accuracy
  you'll see next (98.06%) isn't inflated by memorization."

tb_artifact_detect.py -- say this:
  "I noticed some TB X-rays visually had a color tint or a white
  redaction box burned into the image. If that artifact correlated
  with the disease label, the model could learn 'tint = tuberculosis'
  instead of actually reading the X-ray -- a shortcut, not real
  learning. This quantifies that risk."
  Point at: "Tuberculosis: 372/700 flagged" (370 of them tinted)
  versus "Normal: 13/3500 flagged".
  "Over half the TB images carry the artifact, almost no Normal ones do.
  We cleaned both classes the same way: desaturated the tint, inpainted
  small boxes, and dropped the 72 images with large boxes. It's also why
  a tinted TB image can be rejected by the color check in the live app."

One-line summary if asked "why does this matter":
  "Because a high accuracy number means nothing if the model got
  there by cheating -- these two scripts show where it could have,
  and what we did about it."
