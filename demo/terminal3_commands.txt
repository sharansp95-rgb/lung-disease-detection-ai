WHAT TO EXPLAIN
====================================================================

While it's loading, say this:
  "Watch the startup -- it reloads every checkpoint and re-verifies
  its claimed accuracy against fresh data before it'll process
  anything. If a checkpoint didn't match, it refuses to run. That's a
  guard against ever silently serving a stale or wrong model."

Before run 3, say this:
  "Every image goes through four checks before a prediction is even
  attempted: a blank/color-content check, a sanity gate that tells a
  real scan from a random photo, a modality gate that confirms X-ray
  vs CT, and an out-of-distribution check that rejects anything too
  far from the training data. Only after all four pass does the
  disease classifier run."
  After result: "Benign, 90% confidence -- and the probabilities for the
  other classes are shown too, not hidden."

If using the batch run, after the SUMMARY table say this:
  "Models were loaded and re-verified once; after that each image took
  about a second through the full defended pipeline -- the last one is
  the CT slice I sent down the X-ray path on purpose, and it was refused."

Before run 4, say this:
  "Now I'll deliberately feed the same CT slice through the X-ray path."
  After REJECTED: "It refused to answer instead of confidently giving an
  X-ray diagnosis for a CT slice. The X-ray sanity gate caught it first
  (the web app runs the same gate first, so it rejects this slice the
  same way); if a CT slice ever got past it, the modality gate would
  still say 'this looks like a chest CT scan, not a chest X-ray'. That's
  the difference between a classifier and a defended pipeline."

If a tinted TB X-ray gets rejected at the color-content check:
  "This is the artifact from Terminal 1 showing up live -- the pipeline
  is catching its own known data-quality issue instead of risking a bad
  call."

If the report says "template_fallback" (no internet / no key):
  "That's the plain-language report generator falling back to a
  template because it couldn't reach the LLM -- the prediction pipeline
  itself doesn't depend on it."

You CAN now say "the CLI runs the same models and the same pipeline as
the web app" -- predict_cli.py imports backend/main.py and calls its loader
and gate functions directly (verified 2026-10-13).
